== Description ==

**SitePulse** tells you **exactly what slows your site** and **what to do about it**, directly from your WordPress dashboard.
Activate it, and within seconds you will see which plugins are heavy, which external calls are slow, and how to make your site faster.

== External Services & Data Privacy ==

**SitePulse** uses an external service to provide enhanced features including PageSpeed analysis and AI-powered diagnostics.

### 🔗 External Service Integration
SitePulse communicates with **api.sitepulse.me** (operated by the plugin developer) to provide:
- **PageSpeed Reports** – Google PageSpeed Insights analysis with performance scores, Core Web Vitals metrics, and page screenshots
- **AI Diagnostic Reports** – AI-powered performance analysis and optimization recommendations
- **Remote Management (optional)** – lets your SitePulse dashboard show this site's backups (UpdraftPlus or BackWPup) and its plugin, theme and WordPress updates, and start, cancel or set up its backups. It stays off until you turn it on for the site in your SitePulse dashboard, and you can block it in SitePulse's settings.

### 📊 What Data is Collected?
To provide these enhanced features, SitePulse sends **only performance-related metrics** to the external API:
- Plugin names, versions, and slugs installed on your site
- WordPress hook execution times and memory usage
- API request URLs and response times
- Site domain name
- Performance statistics and load times

### 🔒 What Data is NOT Collected?
SitePulse is designed with privacy in mind and **does NOT collect**:
- ❌ Personal user data (names, emails, passwords, IP addresses)
- ❌ User content (posts, pages, comments, custom data)
- ❌ Database content or sensitive information
- ❌ Customer or visitor information
- ❌ Any personally identifiable information (PII)

### 🔁 Remote Management
While Cloud Services (PageSpeed & AI Reports) are on, the site checks in with api.sitepulse.me every hour, and every 5 minutes while remote management is on. A check-in sends the SitePulse and WordPress versions, which backup plugin is active, whether remote management is blocked on the site, and how WP-Cron runs there: the address of wp-cron.php, whether WP-Cron is turned off and how long scheduled tasks have been waiting.

Only while remote management is on, the site also sends:
- Plugin and theme names, versions, whether they are active, their auto-update setting and available updates
- WordPress, PHP and database versions and the site language
- Backup schedules, how many backups are kept, storage types, the result of the last backup and the dates and sizes of recent backups
- Events when plugins, themes, translations or WordPress are updated, a plugin is activated or deactivated, the theme changes or a backup finishes
- Page speed figures from SitePulse's profiler: once a day, the time plugins, themes and WordPress took per page load the day before (with the five slowest), and after each update, the updated item's time on the full day before and the full day after it
- PHP fatal errors in SitePulse's error log: the first line of the message (up to 300 characters), the file and the line
- How far a running update or undo is: its step, the backup's progress and the item it is on

While remote management is on, the dashboard can also:
- Start or cancel a backup, and apply backup settings saved in your dashboard (schedules, how many backups to keep, which parts of the site to include) to UpdraftPlus or BackWPup. It restores a backup only when you undo a safe update from the dashboard (see below), and never deletes backups or changes where they are stored.
- Update plugins, themes and WordPress, on request or automatically under the site's update policy (by default security and minor updates, three days after release, between 1 and 5 am site time). Updates run through WordPress's own updater, so they come from WordPress.org or a premium plugin's own updater, never from api.sitepulse.me. Each update is preceded by a backup and followed by a check of the home page, wp-admin and, with WooCommerce, the cart and checkout; a plugin or theme that breaks them is rolled back to its previous version.
- Run a safe update of one plugin or theme. First the plugins (or themes) folder and the database are backed up with UpdraftPlus or BackWPup; without a backup plugin there is no backup. SitePulse's screenshot service loads the site's monitored public pages (the home page by default) just before and just after the update and compares them. If a page changed a lot or stopped loading, the dashboard offers to keep the update or undo it. With an UpdraftPlus backup, undoing restores that folder and the whole database to the time of the backup, so anything saved since (such as orders, comments or form entries) is lost; otherwise it reinstalls the previous version from WordPress.org. After an undo, WordPress's own automatic updates do not install the undone version again, for 90 days or until a newer version is installed.
- Turn WordPress's own automatic updates on or off for plugins and themes.

Remote management runs in WP-Cron, which WordPress only runs when the site gets visitors unless a server cron job runs it. So while remote management is on, api.sitepulse.me requests the site's wp-cron.php, at most once a minute, when the dashboard has work waiting for the site or the site has stopped checking in. That request sends no data; with `?sitepulse_check_in=1` the site checks in during that run instead of at its next scheduled check-in.

Requests are signed with the site's SitePulse license, or with a key the dashboard rotates for remote management; the license key itself is never sent. Remote management never sends backup files, passwords, storage credentials or site content, and SitePulse never installs code from api.sitepulse.me. Turn on "Block remote management" in SitePulse's settings to stop it on this site at any time, whatever the dashboard says.

### ⏰ Data Transmission Schedule
- You can view what data will be sent in the SitePulse dashboard before transmission
- Transmission only occurs when enhanced features are enabled

### 🔐 Your Control & Privacy
- All data transmission is for the purpose of providing PageSpeed and AI diagnostic features
- You can disable these features at any time from the plugin settings
- The plugin continues to work locally without external features
- No data is sold or shared with third parties

== Frequently Asked Questions ==

= Can I try SitePulse without installing it? =
Yes! You can instantly try SitePulse using WordPress Playground — a browser-based WordPress environment. Click [Try SitePulse Demo](https://playground.wordpress.net/?plugin=sitepulse&login=yes&url=/wp-admin/admin.php?page=wpsp_sitepulse) to launch a temporary WordPress site with SitePulse pre-installed. No account or installation required.

= Does SitePulse slow my site down? =
No. SitePulse is built to be lightweight and runs asynchronously. Profiling is optional and can be toggled off anytime, or paused entirely from the SitePulse toolbar menu ("Pause monitoring") without deactivating the plugin.

= How do I find out why one specific page is slow? =
Open the page on your site and choose **SitePulse → Analyze this page** in the toolbar, or go to **SitePulse → Page Analysis** and paste its address. SitePulse loads the page a few times as a logged-out visitor and shows how long WordPress needs to build it, how much of that time each plugin and your theme take, every external request the page makes, and what to do about it. It works for any front-end address: products, posts, pages, archives, your shop and search results.

= Page Analysis says my server could not load the page. What now? =
Some hosts, firewalls and password-protected staging sites block a site from requesting its own pages. Click **Open the page and measure my visit**: the page opens in a new tab, SitePulse measures that visit, and the report appears in the first tab. The same happens if a page cache or CDN answers instead of WordPress.

= What time period do the warnings and rankings cover? =
The last 24 hours. Speed warnings, Plugin Activity, scores and AI diagnostics are based on the time each plugin's and theme's own code adds to a page load during the last 24 hours. A plugin you fixed, updated or deactivated stops being flagged within a day, and code that runs very often but quickly is not flagged however much its time adds up. Activity of code that has not run for two days is removed. The External Requests screen keeps its full log.

= Can I pause SitePulse instead of deactivating it? =
Yes. Choose **Pause monitoring** in the SitePulse toolbar menu (or "Pause instead of deactivating" when you deactivate). SitePulse stops measuring page loads, so it adds no profiling overhead, and keeps your settings and history. Choose **Resume monitoring** when you need it again.

= Does SitePulse use external services? =
Yes, but only for optional enhanced features. SitePulse can communicate with api.sitepulse.me to provide PageSpeed reports and AI diagnostics. The core monitoring features work 100% locally without any external connection. Only performance metrics (plugin names, load times, memory usage) are sent — never personal data or user content.

= What data does SitePulse send externally? =
When enhanced features are enabled, SitePulse sends only performance-related data: plugin names/versions, hook execution times, memory usage, and API request metrics. NO personal information, user data, database content, or sensitive information is ever collected or transmitted.

= Can I see my backups and updates in the SitePulse dashboard? =
Yes, with UpdraftPlus 1.26 or later or BackWPup 5 active. Turn remote management on for the site in your SitePulse dashboard to see its backup schedules, recent backups, plugins, themes and available updates, start or cancel a backup, apply backup settings you saved in the dashboard, and update plugins, themes and WordPress safely: after a backup, one at a time, with a rollback when an update breaks the site. You can block it from SitePulse's settings at any time. It is not available on multisite networks yet.

= Can it work with WooCommerce or multisite? =
Yes. Page Analysis works on any front-end address, including WooCommerce product, shop, cart and category pages, and SitePulse runs on multisite environments.

= Is this a "Lite" version with limited features? =
No. This is the Core version of SitePulse. It is a fully functional, unlimited performance monitor. We are building a separate Pro version for advanced historical data and AI features, but the features you see here today will remain free forever.

= How do I join the Pro waitlist? =
You can sign up to be notified when Pro launches at [sitepulse.me](https://sitepulse.me/).

* New: Remote management (optional). Your SitePulse dashboard can show this site's plugins, themes and available updates, plus a history of updates, plugin changes and backups, and update plugins, themes and WordPress, on request (on one site, or on all your sites at once) or under an update policy (by default security and minor updates, after three days, at night): a backup first when UpdraftPlus 1.26+ or BackWPup 5 is active, then one update at a time through WordPress's own updater, each checked on the home page, wp-admin and WooCommerce's cart and checkout, and rolled back when it breaks them. WordPress now sees them again; SitePulse still logs each one.

It now says when the queued scan was requested and when to check again, counts the findings, and explains a refusal (daily limit, Pro license, SitePulse temporarily unavailable).
